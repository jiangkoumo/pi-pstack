## 实现范围

固定上游仍为 `f713f14203cd6420cec13cd7c55c32d598dbab68`（pstack 0.15.25）。生成器读取 `docs/port-map.json` 和 `docs/source-files.json`，在生成与只读检查两种模式中都验证全部 15 份归档原文的 Git blob 指纹，并核对 inventory 的 82 项资产归属。

当前只生成 14 个 skills/ 资源（11 个技能、三个流程）。目标路径必须等于原始技能路径去掉 pstack/ 前缀后的路径，拒绝目录穿越、其他目录、重复目标和符号链接。所有校验在写入前执行；同内容不改写文件。agents/ 尚不属于当前生成范围，P3 必须另行扩展 schema 和权限验收。

六个原文正文保持不变的技能使用 inherit-body，只接受 name、description、disable-model-invocation 三个已支持的单行字段。未知字段、重复字段、多行语法和调用策略变更均拒绝；需要改变策略时须采用显式审阅的覆盖，不静默替换值。

八份语义覆盖存为 adapters/pi/overrides/**/*.template。它们是可再生构建的源模板，随源码包保留，供 npm run generate/check 使用；不属于独立 Markdown 文档。相对链接按照生成目标的位置校验。生成器确认所有模板均有归属，并拒绝 skills/ 中任何扩展名的未归属文件。发布链接检查不再跳过覆盖目录内的 Markdown 文档，且要求该目录没有以 .md 结尾的发布文件。

每个 ported 条目有 dependencies 数组，列出生成后正文中所有本地 Markdown 链接目标，要求唯一、排序并与实际链接一致。指向技能的依赖必须同时在生成清单内；文档和 harness 依赖须在允许范围内且真实存在。数组是本批显式依赖闭包，不宣称可以自动识别任意自然语言中的隐含依赖。未来加入脚本、外部技能或新格式，须先扩展适配规则与验收，不自动纳入支持范围。未适配资产的 dependencies 为 null，历史 evidence 仍指向 P1/P2，不冒充生成后行为证据。

## 维护方式

修改 adapters/pi/ 中的映射或 .template 源模板，以及 docs/port-map.json 的显式清单，再执行 npm run generate。upstream/ 保持固定原文，变更基线时单独审阅 SHA、指纹与差异。不要直接编辑 skills/ 输出。npm run check 同时执行资源检查和生成器失败路径测试；npm run check:generate 是只读检查。
