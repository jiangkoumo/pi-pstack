## 预期包结构

以下为目标结构。当前已有 package.json、skills/、upstream/ 及建档文件；extensions/ 与 agents/ 尚未创建：

```text
pi-pstack/
├── package.json
├── extensions/
│   └── index.ts
├── skills/
│   ├── poteto-mode/
│   │   ├── SKILL.md
│   │   └── playbooks/
│   ├── correct/
│   └── principle-*/
├── agents/
│   ├── poteto-agent.md
│   └── comment-sicko.md
├── docs/
├── LICENSES/
└── THIRD_PARTY_NOTICES.md
```

当前 package.json 只声明 skills。后续代理目录使用 pi.subagents.agents: ["./agents"]，代理 frontmatter 设置 package: pstack。该发现机制已通过 pi-subagents 0.78.0 隔离模块检查，真实会话接入仍需 P3 验收。核心技能不应因为多代理扩展缺失而启动失败；需要多模型的流程应说明依赖缺失，允许的替代行为必须显式标记。

Pi 提供的宿主包按官方文档声明为 peerDependencies，不打进运行时 dependencies。其他依赖只在实际引用时添加。

## 命令与状态设计

下表中两个 /skill: 入口已提供；其余命令仍是拟定接口。技能发现已检查，完整新会话行为验收仍待补齐：

| 入口 | 预期行为 |
| --- | --- |
| /skill:poteto-mode <任务> | 本轮显式应用主技能 |
| /poteto-mode on | 开启当前会话后续轮次的模式 |
| /poteto-mode off | 关闭后续轮次自动应用 |
| /poteto-mode status | 显示模式和能力状态 |
| /setup-pstack | 检测实际可用模型并配置角色 |
| /skill:correct <范围> | 在任务授权范围内识别重复错误并落实约束 |

跨轮模式可评估通过 before_agent_start 注入必要指令、通过 appendEntry 记录非模型状态；恢复时按活动分支重建。具体实现须核实事件与系统提示契约，不能将完整技能每轮无条件重复塞进上下文。

配置文件的确切路径待实现时决定。优先采用独立 JSON，不沿用 Cursor 的 .mdc。必须定义项目配置是否需要信任、是否覆盖用户配置以及如何避免把本机模型选择写成所有用户的默认值。

## 验证策略与完成标准

文档阶段检查来源可追溯、内部链接、清单统计与 Git 状态。实现阶段使用有意义的行为检查：模式状态和错误路径可用自动化检查，技能遵循需要真实任务记录。构建、类型检查或文件存在都不能代替用户可见行为证据。

每阶段交付说明已完成、验证命令与实际结果、未完成和具体阻碍。复杂实现追加 fresh-context 只读审阅，遵守用户对委派的授权。初版完成指 P1、P2、P4 的单代理路径通过；多代理支持需 P3 单独通过。整个上游的完整兼容需额外完成 P5 和逐项能力清单。
